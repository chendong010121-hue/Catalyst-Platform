# 0. Why V0.2 exists

V0.1 established the correct strategic direction:

```text
LINE A — REBIND
Stable WHAT → different HOW → same Evaluation → measured rebinding cost

LINE B — LEARN / HARVEST
External HOW → understand → evaluate → harvest → Stable WHAT → enter LINE A
```

A pre-execution self-audit found that V0.1 is directionally aligned with `CATALYST_CORE_REFERENCE_RESEARCH_V0.1.md`, but two controls were not explicit enough.

## Correction A — long-term direction must not depend on conversation memory

The program cannot rely on ChatGPT, Codex, a human, or another tool remembering the plan from a prior conversation.

Every material stage must re-enter through the current repository truth and explicitly reload the current plan/research/governance sources.

## Correction B — `compose_report@1.0.0` is a deliberately shallow first target

`compose_report@1.0.0` is a deterministic reference Capability. It is useful for proving that Platform Standard semantics can be rebound to a different execution container/binding.

It does **not by itself** prove that a different mature agent Harness can preserve richer Harness-owned behavior such as:

```text
model/tool continuation
context lifecycle
provider continuity
execution recovery
durable session behavior
agentic task completion semantics
```

Therefore V0.2 introduces a claim ladder:

```text
BINDING PORTABILITY
!=
HARNESS-SEMANTIC PORTABILITY
!=
LOW-COST REBINDING
!=
FULL ORGANIZATIONAL CONTINUITY
```

A PASS at one level must never be promoted into a stronger claim without the required evidence.

V0.2 supersedes V0.1 as the **program-control front door**. V0.1 remains preserved as the detailed original stage plan and historical rationale. When V0.1 and V0.2 differ, V0.2 controls execution sequencing, governance re-entry, and claim scope.



```text

```

```text

→ therefore it automatically becomes the selected implementation
```

or:

```text

→ therefore a stronger architectural claim is considered proven
```

# 4. CDP integration

CDP is treated as an **execution discipline**, subordinate to the authority chain above.

It does not become a new Platform object, Runtime object, or architecture layer.

## CDP Mode A — Construction / Integration

Use Mode A when building or integrating a candidate HOW/binding.

Required pattern:

```text
load current authority
→ route and consume applicable methods
→ identify CURRENT WHAT
→ inventory existing internal value/mechanisms
→ inspect mature external alternatives when material
→ REUSE / ADAPT / COMPOSE / RECONSTRUCT / BUILD ONLY GAP
→ construct the minimum complete current responsibility path
→ perform reversible full-path rehearsal
→ aggregate blockers across the path
→ attribute blockers
→ batch the smallest justified repairs/adaptations
→ rerun the complete path
→ READY_TO_FREEZE
```

Mode A rules:

```text
Do not run a formal live proof after every small defect repair.
Do not patch the first visible error before checking the complete current path.
Do not let one local implementation become architecture authority.
Do not automatically create Candidate N+1.
Do not use a fake PASS to replace required real evidence.
```

The purpose is efficient integration: discover the complete bounded blocker set before committing to repeated repair/proof cycles.

## CDP Mode B — Frozen Evidence

Use Mode B after Mode A reaches `READY_TO_FREEZE`.

Required pattern:

```text
freeze exact candidate SHA / external HOW identity
→ independent static/review check
→ explicit real-proof authorization
→ exact formal proof
→ preserve durable evidence
→ independent Evaluation / attribution
→ ACCEPT / REJECT / PAUSE / ROLLBACK
→ STOP
```

Mode B rules:

```text
no mutation inside the formal run
no target repair after run start
no prompt/benchmark/rubric tuning to erase a result
no silent Provider/tool/HOW substitution
no reuse of one run identity after material change
no automatic second real proof because the first failed
```

A failed Mode B proof is evidence. It is not automatic repair authorization.

# 7. Mandatory correction / re-entry triggers

A stage or candidate must STOP automatic continuation and re-enter the relevant Decision Audit when evidence shows any of:

```text
1. a materially different failure appears at the same HOW boundary
2. a load-bearing assumption becomes invalidated or materially uncertain
3. semantic/state authority becomes ambiguous or duplicated
4. a claimed closed gap contains a newly discovered material sub-gap
5. a claimed full replacement is actually partial supersession
6. compatibility/patch debt gains another material branch or exception
7. Provider/model/Harness variance changes a material semantic, safety, or authority outcome
8. a mature external alternative materially changes the total-cost comparison
9. Stable WHAT would need material change merely to fit the selected HOW
10. Evaluation/benchmark would need material rewrite merely to fit the selected HOW
11. Platform Standard/Core would need repeated changes for one HOW
12. binding work is expanding into a generic framework without second-system evidence
13. Rebinding Cost is growing rather than being bounded
14. the current experiment no longer answers the declared uncertainty
15. research/plan assumptions are contradicted by current Product truth
```

Mandatory response:

```text
STOP automatic next-patch assumption
→ preserve evidence
→ restate CURRENT WHAT
→ ask: does this finding block CURRENT WHAT?
→ attribute owner
→ rerun the appropriate audit / alternative comparison
→ obtain new bounded authorization if mutation is justified
```

There is no numeric rule such as `two failures = replace`.

Correction is responsibility- and evidence-driven.

# 9. Claim ladder — prevent false success

## Level P0 — Binding / Standard Portability

Claim:

```text
The same frozen Platform Capability semantics can be mapped through another execution boundary without changing its Stable WHAT.
```

Evidence may use a simple deterministic Capability such as `compose_report@1.0.0`.

P0 does **not** prove mature Harness-semantic replacement.

## Level P1 — Harness-Semantic Portability

Claim:

```text
A Capability/responsibility whose observable success materially depends on execution behavior owned by the candidate HOW can survive replacement of that HOW under the same WHAT/Evaluation boundary.
```

The selected target must actually exercise material HOW behavior.

Possible material behavior may include, only where the Capability genuinely requires it:

```text
model/tool continuation
multi-step reasoning/execution
context/session continuity
execution certainty
recovery/reconcile
durable state
side-effect handling
provider/model lifecycle
```

Do not create artificial requirements merely to make the proof look more agentic.

P1 target selection occurs **after P0 evidence** and must use current governed value / agent-construction / capability-optimization logic as applicable.

Do not invent a new Platform Capability solely to manufacture a Harness test if an existing governed responsibility can provide the needed boundary.

## Level P2 — Rebinding Knowledge Reuse

Claim:

```text
Conformance/migration knowledge learned from HOW B materially reduces discovery/mapping/revalidation cost for HOW C.
```

Requires at least two genuinely different rebinding efforts and measured comparable cost dimensions.

## Level P3 — Learn / Harvest / Second-use Continuity

Claim:

```text
External HOW knowledge can be harvested into durable organizational WHAT and later reused with lower second-use cost, independent of the original implementation container.
```

This is the Waku/Harvest/Recompose line.

No lower level may be presented as proof of a higher level.
