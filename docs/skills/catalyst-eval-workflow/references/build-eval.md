1. Identify one user outcome and the real entry. Record what completion means,
   known valid alternatives, target object/depth and whether this is engineering,
   product-use acceptance, quality comparison or resource-efficiency measurement.
2. Map existing Catalyst entry -> Harness/Runtime -> tools/SourcePort -> Provider/P0
   and credential boundary -> typed validation -> independent Evaluation -> R4 ->
   final artifact/state and effects. Use the inspected source map below; reverify
   identities today. Do not reconstruct a model call or add a new Runner/engine.
3. Reuse cases and historical receipts only within their privacy and evidence scope.
   Assemble draft inputs and separate Owner/reference expectations, with provenance,
   unknown truth and known equivalent answers. Human PENDING remains PENDING.
4. Obtain explicit approval of inputs and grading separately if not already clearly
   authorized in this session. Existing authorization need not be requested twice;
   scope/hash drift must be disclosed. Do not infer business truth from approval to
   send a file. Do not label one hand-crafted public example a general benchmark.
5. Choose deterministic outcome checks first; use original typed Validator and M4/
   project grader for their measured dimensions. Source identity is not entailment.
   An independent human or explicitly authorized calibrated Judge may address
   qualitative truth, never the tested model self-signing its own output.
6. Define the product-use profile and explicit test overlay. Keep source/privacy,
   effects and permissions unchanged. Audit hidden read/call/context ceilings,
   duplicate retrieval, tool-schema availability, finalization and recovery. State
   the anticipated correct-result capacity; do not prove readiness using only an
   empty/unresolved result or a scripted forced tool path.
7. Use the existing Host/capture/R4 and evaluator artifacts. Preserve the same actual
   request/response that receives a grade; record request IDs, provider/model/fingerprint,
   finish reason, call-level usage/cost, tool outcomes, task completion, source coverage,
   policy/limit cause and evaluator status. Derived report rows must point back to
   immutable originals. No paid Judge, retry or extra pilot without its scope.
8. Run eval-audit before proposing a paid pass. Freeze case IDs, repetitions/split,
   grading version, denominators, side effects, request/cost limits and stop conditions.
   The present workflow preparation stops at a reviewable plan, not a real baseline.

## Penguin-derived case organization

Treat the evaluated component and the case set as separate, versioned identities:
one case set may measure different subjects, but each run binds one subject version,
one public task and one independent private evaluation. Before an execution,
freeze the subject, public input and evaluation identities; after it, verify they
did not drift. A test's material, objective, executor, grader and resource limits
are selected per case, not inferred from the project-understanding card. A missing
compatible executor or evaluator is BLOCKED, never substituted with a different task.
This is an adaptation of the Penguin benchmark-design and agent-evaluation Skills;
the Catalyst workflow remains preparation, not a Penguin runner or private sandbox.
