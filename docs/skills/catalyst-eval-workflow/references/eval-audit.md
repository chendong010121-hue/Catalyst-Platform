# eval-audit: qualify the measurement, not the Subject

Read actual config/source and immutable output, not only reports or test totals.
Use recorded results when available; an audit does not grant a new paid run.

Check and record evidence for:
1. **Outcome agreement**: real user task, input scope, expected provenance, enough
   difficulty and diversity, equivalence, independent truth and unresolved labels.
2. **Entry parity**: same product version, prompt/method, tool definitions, parameters,
   model and policies as intended use; enumerate all differences and fixed limits.
   Hidden read limits, missing tools and irrelevant retrieved evidence are harness/
   product concerns, not automatically Subject semantic errors.
3. **Isolation**: independent case state, no prior answers/cache/Git hints or effects;
   Gold/held-out access excluded by actual access boundaries. Prompt instructions or
   a fresh agent do not prove filesystem isolation.
4. **Lifecycle**: natural single/multiple tool choices, repeated inspection, expansion,
   supported/UNKNOWN submission, invalid schema, final reply, cancellation/timeout,
   ledger uncertainty, method leases/handle release, durable result/R4 readback.
   Exercise limits before/after tool completion, not only one happy-path script.
5. **Grader health**: known-good/oracle and wrong/null controls, relevant negative
   examples, original typed contracts, outcome rather than exact tool sequence,
   source locator checks separated from business entailment. A Judge needs human
   calibration and separate authorization; absent truth remains NOT_EVALUATED.
6. **Accounting**: persist all dispatch attempts including errors and retries;
   missing usage is unknown, not zero; reserve before send and reconcile reliable
   usage afterward. Report provider-call time, tool time and total task time separately.
7. **Decision resolution**: sample count, reps, model variance, meaningful effect and
   regression limits. A one-case/one-rep demo can qualify an observed execution, not
   general semantic superiority. Do not report confidence intervals unsupported by
   the design or treat more requests as evidence of better reasoning.
8. **Interpretation**: raw task completion and conditional semantic measurements use
   explicit denominators, both retained. No post-hoc exclusion of hard cases/errors.
   Report PASS_WITH_LIMITS, BLOCKED or NOT_EVALUATED without manufacturing a score.

Return a concise matrix of finding, evidence locator, impact and minimal next action;
separate engineering readiness from live authorization and semantic readiness. Only
unresolved decision-relevant findings block the corresponding phase; a minor issue
must not force a new platform audit.

## Receipt-only audit
If only frozen receipts are allowed or available, audit those observations and
label unavailable current code/config, isolation, effective parameter parity and
independent accounting checks UNPROVEN. A source map or historical report in this
skill is a pointer, not verified live state. Do not expand filesystem or credential
access to manufacture proof. Such a limited audit may support failure diagnosis;
it cannot grant execution or quality qualifications whose evidence is missing.
