# Three distinct contracts

## Product use
A user supplies a goal, admitted sources/context and permitted effects. The product
owns context assembly, retrieval, execution, progress, cancellation and recovery.
The user need not manually choose a call count on every task. Background account,
workspace, provider and safety policies still apply; no promise of unlimited compute.
A task finishes with its requested result or an explicit partial/blocked/cancelled
state. No universal four-read completion requirement is implied.

## Evaluation
An external test definition pins the product entry and operational profile, approved
inputs/expectations, isolation, metric, sampling/reps, resource conditions and failure
classification. Call the real product; isolate only unsafe effects. Document every
policy difference from everyday use. A deliberately constrained test measures the
system under that constraint; it cannot qualify ordinary use without representative
resource conditions. An eval limit is not a new product protocol.

## Iteration
An explicitly authorized experiment consumes developer feedback and changes an
allowlisted candidate. A separate frozen evaluator measures it; neither proposer nor
candidate can edit grading, Owner facts, held-out materials or production governance.
The actor must be declared: Codex-assisted engineering and Catalyst-LLM autonomous
proposal are different experiments. The latter cannot be substituted by Codex edits.
No automatic production winner, activation or Reference promotion.

## Failure classification (declare before running)
Always report user task completion across all admitted attempts. Separately report
comparable measured quality, denominators, excluded reasons and infrastructure health.
- Valid completed answer/artifact: eligible for the declared outcome grader, which
  may give PASS or FAIL. Honest uncertainty can finish a report but leave task unmet.
- Subject failure under a representative declared product policy: system task failure;
  do not remove it merely because the code calls it a tool error.
- Test-injected resource ceiling truncates execution: LIMIT_REACHED / constrained
  experiment; task unfinished, semantic quality unmeasured unless valid partial
  artifacts support a specifically declared partial metric.
- A hidden product read ceiling in a normal-use test: PRODUCT_POLICY_BLOCKED plus
  EVAL_PROFILE_CONFOUNDED; not proof that the underlying model cannot understand.
- Transport/fixture/identity/isolation/usage error: INFRASTRUCTURE_BLOCKED or INVALID;
  preserve all attempts/cost and report full completion rate alongside any conditional
  quality rate. Never silently shrink the denominator or rerun until successful.
- Grader failure or missing independent truth: EVALUATION_BLOCKED / NOT_EVALUATED.

For the October26 public Skill trial, the four-model-call authorization and the
adapter's shared four-read ceiling were separate. Runtime and plugin also have
per-tool controls. Audit all three; do not fix this by silently deleting guards or
teaching Understand to optimize only for this one short experiment.
